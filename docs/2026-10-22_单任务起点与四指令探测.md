# 单任务起点与四指令探测

**通俗说明：先集中教机器人“把书放左格”，让它把这一个任务练好。随后把同一场景恢复到完全相同的位置，只换成“前格／右格／后格”指令，看它能否换目标，还是继续执行学过的左格任务。这样先建立一个简单、可靠的操作起点，并检查单任务适应后的目标偏置。其他三个目标如果从未学会，就不能把测试失败叫作旧能力遗忘。**

用户已授权本实验。三旧任务联合训练不是硬性前提，本轮改为一个旧任务。下列设计在启动训练前固定；工程实现复用原数据、模型与仿真资源，不新增大文件下载。

**已确认结果：6000步左格开发终态正确10/10，已冻结该检查点并启动另一组初态的四指令探测。** 截至17:08:41的成功SSH核查，该探测已在运行；随后SSH在banner阶段超时，四指令最终结果尚未取回，不能宣称目标偏置已经发生或没有发生。见文末状态及证据。

## 1. 本轮能回答多强的问题

- 可以检查：单任务适应后是否获得较高左格完成率，以及换成其他合理指令时是否仍完成左格。
- 有训练前基座对照，可以记录适应前后正确任务／错目标／未完成的变化；若基座原本就不会其他任务，不能声称这些能力后来被遗忘。
- 其他指令下稳定出现左格，支持“已训练目标占据行为输出”的现象，但不单独证明语言信息被抹去或传递路径受损，也不是方法创新的充分证据。
- 后续若从这个单任务起点学习第二个目标，再检查旧左格指令是否转成新目标，才直接进入持续学习损伤研究。一旧任务加一新任务已能构成这类最小验证。

单任务高成功率本身不证明获得了语言目标分辨能力：不读指令、始终放左格也能通过左格测试。一个旧任务加一个新任务，可以研究单目标技能的保持与输出偏置；若要支持“已经获得的指令条件目标选择被侵蚀”这一更强主张，后续应先让至少两个目标在同一场景下依不同指令各自成功。两目标起点即可支持这种更强的判据，没有必须三个旧任务的要求。

## 2. 为什么选择左格

此前三任务运行中，左格在两个6000步模型均为6/10，是当前较容易建立的起点。本次这个选择依据既有开发结果，属于探索性起步选择，不伪装成未看结果的预注册任务选择。

训练只用左格40条示范，验证保留10条，沿用既有轨迹划分。每次更新6个样本均来自左格；与原三任务每目标2样本相比，同等更新次数下左格样本曝光增加。重新计算左格训练数据统计，右／前／后格不进入本轮训练或归一化。不能将新旧差异单独归因为消除了多任务干扰。

数据仍采用已核验的“执行后观测→下一步动作”配对；每条轨迹丢弃最后一帧无后续动作的观测，图像及其他控制约定不变。

## 3. 固定训练及选点规则

| 项目 | 本轮设置 |
|---|---|
| 基座 | 服务器同一原始smolvla_base，完整严格加载 |
| 更新范围 | 冻结VLM，更新原生动作专家与相关投影 |
| 优化 | batch6，lr1e-4，warmup100，BF16，seed20261021 |
| 动作执行 | chunk50、flow10，每次执行10步，20Hz |
| 首轮上限 | 6000步，不自动延长 |
| 预定候选 | 1000、3000、6000步，按此顺序仅测试左格开发表现 |
| 触发门槛 | 开发初态0—9，左格400步终态正确至少8/10 |
| 选点 | 选择第一个达标的预定候选；随后发停止训练请求，保留已冻结候选 |
| 未达标 | 记录所有候选失败，不把最后一个模型自动称为高成功率起点 |

GPU0训练，GPU1做评估；基座对照与训练可并行，评估阶段顺序执行，避免两个评估争用同一卡。候选选择不参考其他三条指令的成绩或错左格比例。

8/10是本轮冒烟操作门槛，样本少，不意味着真实成功率已被统计证明大于80%。本轮不使用独立资格初态10—29；之前三任务资格标准没有被改写。

## 4. 达标后的四指令测试

在另一组固定初态30—39，逐个恢复同一canonical XML、完整物理状态、settle流程和推理种子，再分别运行前／左／右／后四条指令。每个模型40回合、每回合400步。基座与适应后模型使用同一左格训练统计，基座名称明确标为`base_with_training_stats`，不是未经任务尺度校准的默认部署结果。

基座先做这40回合对照；只有某个预定候选通过左格开发门槛，才用冻结候选执行适应后的40回合。两个模型的全部初态、场景哈希及种子需要逐条件一致，发现不一致即停止比较。

记录一个“指令×最终实际目标”表，列为前／左／右／后／未完成／歧义。保留所有失败，不仅统计完成的回合。

重点报告：

1. 左格指令在这组初态是否仍达到8/10。这是未参与选点的起点检查；低于8/10时，报告“开发达标但起点独立检查不足”，不继续换候选反复考同一组来挑结果。
2. 其他三条指令各自的正确完成率及完成左格的次数，分母各为10，总计30。
3. 只在“同初态下左格控制指令成功”的状态上，其他三指令有多少仍完成左格。此条件分母明确为3×左格控制成功初态数，未完成也保留在分母；无成功控制初态时比例为空。
4. 基座原本正确的其他任务，在适应后变成正确、左格、其他错格、未完成或歧义的配对转移。基座本来不成功的回合不记为遗忘。

初态30—39从本轮起已用于此探索性探测，不再称未使用测试集。初态40—49与资格10—29保留。

## 7. 中途核对基准后的独立补充口径

原流程称为A：按启动前固定的第400步终态选点，继续运行，不改既有成绩或门槛。1000步为终态2/10、曾成功6/10；3000步为终态0/10、曾成功5/10。两点均未达标。

本地LIBERO参考[metric.py](../third_party/LIBERO-reference/libero/lifelong/metric.py)累计`dones[k] = dones[k] or done[k]`并以累计成功计分；环境[step实现](../third_party/LIBERO-reference/libero/libero/envs/bddl_base_domain.py)将done设为任务成功判据。因此，“过程中曾完成请求目标”和“继续动作直到400步仍正确”是不同问题，后者额外考察结果保持。将后者作为这次单任务起点的唯一要求偏严。

在查看6000步成绩之前，另外固定补充流程B：**只用6000步这一终点，不在1000/3000/6000间按新口径挑点**。若6000步开发“曾成功”达到8/10，则冻结同一模型，做预定30—39初态四指令测试；如果A已对6000步做过同样测试则复用，不重复刷分。若6000步按此口径仍低于8/10，记录未建立起点，不强行开展成功后的目标偏置结论。

补充报告同时列出：

- 请求目标曾成功率：与参考代码累计成功定义一致；复位、horizon等其他设置仍为本项目协议，不能称完整复现官方benchmark。
- 首次到达任一目标的矩阵：用于观察目标选择轨迹，首次正确/错误判据可能仍在夹持过程中成立，不能据此认定已经松爪放稳。
- 400步最终目标矩阵：原有结果保持及错目标完成指标。
- 其他指令下到达过左格、但从未达到请求目标的次数，以及最终仍在左格的次数，分别报告。

本轮仍实际执行完整400步以保留晚期行为；累计成功从逐步日志直接读取。它等价于在相同轨迹前缀中检查是否曾满足任务成功条件，但不把后续破坏隐藏掉。所有失败保留在对应分母中。

补充入口：[stage1_single_task_benchmark_followup.py](../scripts/stage1_single_task_benchmark_followup.py)。它等待A正常结束，只使用固定终点和同一对照组，不改训练权重。源脚本以独立副本运行并记录SHA256，底层评估代码仍保持实验提交`6c9adc00`。
