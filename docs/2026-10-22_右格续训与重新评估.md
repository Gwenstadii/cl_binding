# 右格续训与重新评估

**通俗说明：先不换方法，只让当前右格模型再练一段时间。每隔固定步数，用另一组场景只考右格；右格达到较高成功率后冻结模型，再检查前／左／右／后各20回合。这样判断多训练是否能补上右格能力，同时保留旧左格损伤的完整记录。**

## 1. 为什么值得增加步数，但还不能断言有用

E002右格过程成功和最终正确均为9/20，其余11回合始终没有完成右格；低分不是主要由“成功后又破坏”造成。数据配对、归一化行为、优化器更新及模型保存重载均通过核验，未发现训练没有实际进行或统计切换的证据。

训练后期仍在改善：3501—4000步平均loss为0.2163，5001—5500步为0.1849，5501—6000步为0.1767。它支持进一步测试更多更新，但示范上的动作拟合loss不直接等于闭环任务成功率。当前尚未区分：更新次数不足、左格起点对新任务的干扰、对40条右格示范的泛化不足及执行控制问题；不能只凭低成功率确定根因。

本轮只改变训练预算，保留模型更新范围、数据、归一化、学习率及执行参数。若续训仍无法稳定提高右格，则停止把问题简单解释为步数不够。

## 2. 如何续训

- 从右格 `outputs/sequential/left_then_right_20261022_01/checkpoints/006000` 恢复完整权重、优化器、调度器和随机数状态，继续右格6001步起的训练；不是从基座重训，也不重置优化器。
- 原训练配置保持逐字段一致，通过 `--max-steps 18000` 明确覆盖本次上限。这里9000／12000／15000／18000均是**累计右格训练步数**，在旧左格6000步之外计数。最多再训练12000步。
- 右格40条训练及10条验证不变；VLM冻结，动作专家／相关投影更新；batch6、lr1e-4不变，继承已有调度状态，不重新warmup；原左格归一化不变，无回放或蒸馏。
- 原006000检查点和E002证据保留；新检查点追加到原训练目录，新启动命令、源码及实际预算在独立续训运行目录记录。训练日志从6001步追加。

## 3. 固定选点规则

1. 先补当前右格6000步模型在开发初态0—19上的20回合，作为开发基线，不作为本轮新选点。
2. 按9000、12000、15000、18000步顺序，只检查右格的同一20个开发初态。
3. 第一个右格“曾成功”和“400步最终正确”均至少16/20的候选即冻结；发独立停止请求，之后用已冻结候选做四指令评估。训练可能已经超过该候选，但不会改写其权重。
4. 如果所有候选未达标，只对固定18000步终点做完整评估，并明确记录未建立高成功率新任务；不根据旧任务遗忘或配对成绩挑更有利模型，不无限加步数。

每次右格开发均20回合。为此本轮开发使用0—19：10—19从此前未使用资格区转为开发用途，20—29仍未用于本轮选点或最终评估。独立生成评估配置，原E002训练配置和划分记录不改写。

## 4. 重新评估什么

选定后前／左／右／后各20回合，共80回合，初态仍30—49，每回合400步；用两张3090并行完成，逐条核对状态、场景及推理种子。该组已在E002用于探测，这次用于配对比较，不称全新或未使用测试集。

同时比较三个模型：

- 原始左格起点：使用E002已保存的80回合，左格过程20/20、终态19/20。
- 右格6000步：使用E002已保存的80回合，右格9/20、旧左格0/20。
- 本轮选定的较长右格训练模型：新跑80回合。

这样既能看右格是否从45%提高，也能看更充分学习右格后旧左格是否仍未完成、转成右格，或发生其他变化。比较的是不同训练预算，不据此声称同预算方法优劣；仍需多种子及后续机制研究。

cd /home/lzx/cl_binding
.venv/bin/python -u scripts/stage1_right_continue.py \
  --plan configs/stage1_right_continue_v1.json \
  --run-dir .server/right_continue_20261022_01
