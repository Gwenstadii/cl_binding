# 四任务顺序训练与早晨验收

**接着已经选定的“左→右”模型，先只教前格12000步，评估一次；再从前格终点只教后格12000步，再评估一次。两次均测前／左／右／后各20回合，观察新任务学到多少，以及旧指令转向了什么目标。整段后台自动执行，结果不会因成功率低而被隐藏。**

## 固定训练计划

| 阶段 | 起点 | 本阶段训练 | 评估 |
|---|---|---|---|
| 已完成：左→右 | 左格6000步→选定右格9000步 | 本轮复用，不重训 | 复用E003四指令80回合 |
| 三任务：左→右→前 | 右格`009000`，不采用未选中的`010001` | 只训前格，固定12000步 | 四指令各20回合，共80；三任务汇总只包含左／右／前 |
| 四任务：左→右→前→后 | 前格`012000` | 只训后格，固定12000步 | 四指令各20回合，共80 |

- 每个新任务40条训练、10条验证，轨迹划分及观测→下一步动作的时序约定不变。
- 继承模型权重及最初左格归一化；每次切换新任务时重建优化器／调度器，沿用E002任务切换方式。冻结VLM、更新动作专家及相关投影，无回放、无蒸馏。
- batch6、lr1e-4、warmup100，BF16；chunk50、flow10、每次执行10步，20Hz。
- 两个任务均完整12000步，固定终点，不做基于成绩的早停或选点。每3000步保存并验证重载；前格分数低也继续后格。
- 两份数据在GPU训练前都先完成转换与逐帧核验。数据自身统计和实际继承的归一化来源分别记录；后格此时按计划进入训练，不再沿用“后格永不进入训练”的旧阶段假设。

## 评估和解释

每阶段用固定初态30—49，共同物理状态、场景XML、推理种子，400控制步；同时记录曾成功、最终成功、首次目标、最终实际目标、未完成及歧义。三任务阶段后格尚未训练，只作为额外诊断，不计入三任务汇总，也不把它的失败算成遗忘。

既与立即前一阶段比较，也与每个任务刚学完的历史阶段比较。例如三任务阶段之前左格已经0/20，不能把这一损失重新称为“学前格才造成的遗忘”；右格从15/20如何变化才是本次立即前后保持的有效分母。原左格起点、右格9000步、前格12000步、后格12000步会共同列入报告。

每个终点评估分给两张3090并行执行，分别负责前／左和右／后；阶段评估结束后自动进入下一任务。若评估进程发生运行错误，最多重试一次，保留原失败输出；不会因为分数低重试、换模型或过滤失败。真正的训练／数据／配对错误会明确记录为失败，不能用旧结果冒充完成。

本轮实际新增24000步新任务训练及160回合评估；历史两模型的160回合直接复用。模型祖先链为左6000→右9000→前12000→后12000，总有效训练步数为39000；右格阶段未被选用的额外更新不进入此祖先链。仍是单种子、单旧技能起点的探索性序列，不预先保证各新任务能达高成功率。

## 运行与验收

计划：[stage1_four_task_sequence_v1.json](../configs/stage1_four_task_sequence_v1.json)；入口：[stage1_complete_sequence.py](../scripts/stage1_complete_sequence.py)。

```bash
cd /home/lzx/cl_binding
.venv/bin/python -u scripts/stage1_complete_sequence.py \
  --plan configs/stage1_four_task_sequence_v1.json \
  --run-dir .server/four_task_20261023_01
```

服务器运行目录：`/home/lzx/cl_binding/.server/four_task_20261023_01`。

训练模型：

- 三任务：`/home/lzx/cl_binding/outputs/sequential/four_task_20261023_01/stage3_front/checkpoints/012000`。
- 四任务：`/home/lzx/cl_binding/outputs/sequential/four_task_20261023_01/stage4_back/checkpoints/012000`。

早晨先看这两项：

```bash
ssh scutlab
cd /home/lzx/cl_binding
cat .server/four_task_20261023_01/COMPLETE.json
cat .server/four_task_20261023_01/report.md
```

`COMPLETE.json`仅在两次12000步训练、两次80回合评估、结果汇总及证据包均成功后生成。`report.md`自动呈现各阶段四任务成绩和目标混淆矩阵，曾成功与终态正确分别列出。

进一步查看：

```bash
cat .server/four_task_20261023_01/run_summary.json
cat .server/four_task_20261023_01/stage3_front/summary.json
cat .server/four_task_20261023_01/stage4_back/summary.json

```

各阶段另有`episodes.jsonl`、`comparison_to_previous.json`和`comparison_to_acquisition.json`。视频及逐步日志在对应阶段`eval1_part0/`和`eval1_part1/`中；若发生运行错误重试，以汇总注明的尝试号为准。证据包仅含小文件，不含权重、示范图像及大日志。

先验收三任务阶段时，无须等待四任务结束：

```bash
cat .server/four_task_20261023_01/stage3_front/COMPLETE.json
cat .server/four_task_20261023_01/stage3_front/summary.json
cat .server/four_task_20261023_01/report.md
```

阶段完成标记只在该阶段12000步训练、80回合评估和配对核验全部成功后生成；此时后格可能已经开始训练。全局`COMPLETE.json`仍只代表四任务全流程完成。

按此前双3090速度，两次训练加评估预计约1小时50分—2小时20分；以实际负载和完成标记为准。后台不依赖当前SSH窗口，也不需要睡前继续发消息。完成后的科研结论经读回核验再加入根目录[实验记录](../实验记录.md)，不会提前填入未观察的结果。
