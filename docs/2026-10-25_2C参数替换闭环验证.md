# 2C：参数替换的闭环验证

日期：2026-10-25，只做评估。混合模型由封存的双目标父模型（左+前12k）和2A的FT4终点（种子s1）拼成，构造方法见`scripts/stage2_param_swap.py`。每个混合模型在四条指令×配对初态20—39上评估，每回合400步，协议与2A相同。证据在[`docs/results/2026-10-25/stage2c_swap_closedloop/`](results/2026-10-25/stage2c_swap_closedloop/)。

## 2. 结论

1. **读取VLM特征的投影不是替代所在。** 把父模型的读取k/v投影换回FT4后，左、前指令仍有32/40回合去右格；把FT4的这组投影换进父模型，左格基本不受影响（17/20）。开环和闭环在这一点上一致。
2. **替代无法定位到专家的某一半。** 换回任何一半都没有恢复旧目标。把FT4的任何一半换进父模型，都没有把旧指令导向右格（0/40），而是送去后格或另一个旧格。所有混合模型的新右格指令都几乎完全失效（0–1/20）。
3. **混合模型出现“嵌合”行为。** 例如“父模型＋FT4前8层”把前指令放进后格（16/20），未学的后格指令反而成功17/20；“FT4＋父模型后8层”把左指令放进后格（17/20）。这说明两个模型的内部表示已经不能互换：专家各层是一起适应的，目标到动作的映射分布在整个专家里，不是由某个可拆卸的模块承载。
4. **开环代理指标不能用来定位机制。** 开环下“父模型＋FT4后8层”有254/400帧最接近右格参考，闭环中却0/40回合去右格。单个动作块的相似度不能代替闭环里的目标选择，机制主张必须以闭环干预为准。2B文档中基于开环的“集中在后8层”已改正。

## 3. 对论文叙事的影响

- 机制部分应写成：VLM编码和读取投影都不是替代的位置，替代是整个动作专家协同适应的结果；参数级的模块替换无法分离它。这和“按函数约束的回放有效”是一致的。
- 可以预测：只冻结或只保护某一模块（读取投影、某几层、某个LoRA位置）防不住替代。这个预测可以直接用实验检验，例如冻结后8层或只训练前8层的FT对照，比继续做参数拼接更有信息量。
- 如果要更细的机制证据，下一步应改做**激活修补**：在同一条推理里，把父模型某层对旧指令的隐藏状态替换进适应后的模型。权重替换会破坏各层之间的协同，混合模型容易出现嵌合行为，干扰解读。
