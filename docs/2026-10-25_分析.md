# 10/25 分析：怎样确认语言条件读取受损，以及怎样恢复和预防

> **先用通俗的话说明我们要做什么：** 机器人原来听到“书放左格”和“书放前格”，会分别照做；继续学右格后，却可能听什么都放右格。我们要检查：它是没有正确利用指令，还是动作控制本身发生了变化。做法是只恢复模型中一小段“读取指令相关信息”的计算，观察能不能重新按指令放对；再反过来，把新计算放进原来正常的模型，看能否复现同类错误。证据吻合后，才尝试用有限旧样本和有针对性的训练，让模型自己恢复，并在以后学新任务时少发生这种损伤。

**文档用途：10/25 讨论稿。** 依据为 10/24 第二阶段计划、已有 E001—E009 实验记录及当前固定版本代码。本文没有新增训练或仿真结果；所有机制、恢复效果和资源安排均为待验证设计。这里的“证明”指有边界、可复验的因果证据，不指已经找到了唯一语言模块。

前置文档：[10/24 第二阶段计划](2026-10-24_第二阶段训练计划_普通回放与目标选择保护.md)、[第一阶段总结](../实验记录.md#phase1-summary)。本文不改变已有资格标准，也不自动启动后续训练。

## 1. 我们现在知道什么，尚不知道什么

### 1.1 已有行为证据

E007 从联合左＋前 12000 步模型出发，只学习右格。父模型在历史 20 个初态上，左／前最终正确各 16 次，其中 13 个同一初态两条指令都能最终正确。学习右格后，两条旧指令最终正确均为 0。

只看训练前最终正确的条件，旧左的 16 个条件中，12 个最终变成右格、4 个未完成；旧前的 16 个条件中，9 个最终右格、7 个未完成。这支持“部分已获得的条件选择能力退化，并出现最新目标偏置”。这 32 个条件共享 20 个物理初态，不能当作 32 个独立场景。详见[实验记录中的 E007](../实验记录.md)。

E009 还提醒我们：目标选择和结果维持要分开。新后格 19/20 曾成功，但只有 6/20 最终正确；不能把先放对、随后又破坏的情况，都说成一开始没听懂指令。[E009 原始报告](results/2026-10-23/dual_right_then_back_v1/report.md)

### 1.2 目前不能直接得出的结论

- 不能说语言信息已经完整保留，只是没有被读取。
- 不能说已经定位到某个注意力头、Q/K 投影或语言专属通路。
- 不能说普通 ER 无效：截至本地记录，第二阶段尚未启动。
- 不能说新右格已稳定掌握：E007 的最终正确是 12/20。
- 不能把历史双目标父模型追认为正式合格 R0：其同状态双指令共同终态为 13/20，尚未通过原资格标准。

因此，现有模型适合开发性诊断；正式机制结论仍需 10/24 计划中 2B 的合格起点、封存物理状态与独立训练复验。

## 2. “语言读取通路”在当前模型里究竟是什么

### 2.1 先理解信息怎样变成动作

当前 SmolVLA 的简化流程是：

    图像、指令 → 冻结的视觉语言计算 → 图像/语言位置的信息
    机器人状态 → 可训练的状态投影 → 状态位置的信息
                         ↓
             动作专家读取这些前缀信息
                         ↓
        动作专家内部处理、动作输出投影、动作生成
                         ↓
                  机器人实际执行

“前缀”可以理解成动作专家在生成动作前可读取的一份信息材料。它不只有语言，还包括图像和状态。动作专家也不是单纯的语言接收器，它同时负责运动生成。

当前设置冻结 VLM，直接更新动作专家及相关投影，不是整套 VLA 全参数更新，也没有启用 LoRA。实际运行仍以保存的配置、优化器参数清单与权重核验为准。[配置](../third_party/lerobot/src/lerobot/policies/smolvla/configuration_smolvla.py)、[冻结与读取实现](../third_party/lerobot/src/lerobot/policies/smolvla/smolvlm_with_expert.py)

### 2.2 一个需要纠正得更精确的地方

“VLM 冻结，所以整个前缀完全不变”不成立，因为状态投影会训练。

但反过来说“状态投影变化，所以所有图像和语言表示都可能被它改写”也不符合当前掩码。代码明确限制：**图像和语言位置不能读取状态或动作位置。** 在图像、指令、预处理、冻结权重及运行模式相同的条件下，图像／语言前缀子块理论上不受状态投影漂移影响；状态子块则可能改变，并在后续计算中包含图文融合信息。

所以要逐层、逐块实测：图像位置、语言位置、状态位置的输入与 K/V 是否变化。完整前缀和图文子块必须分开下结论。若理论上应相同的图文子块出现明显差异，先检查输入、预处理、权重、运行模式、掩码与数值误差；不能马上把它叫成语义损伤。[前缀与状态掩码](../third_party/lerobot/src/lerobot/policies/smolvla/modeling_smolvla.py)、[掩码构造](../third_party/lerobot/src/lerobot/policies/common/vla_utils.py)

另一个边界是：图像位置可以已经包含语言影响，语言位置也可以包含视觉信息。因此“只替换语言 token”不等于隔离了纯语言语义模块。

### 2.3 本文实际要验证的假设

> 在后续任务更新后，某个动作专家接口传递或使用指令相关信息的方式改变；这个改变参与了旧指令的目标选择错误。

它至少包含三种不同可能：读取分配变了、被读取内容的变换变了、信息读入后没有被正确使用。必须允许状态输入、动作读出或执行损伤成为更好的解释。

## 3. 哪些证据够，哪些证据不够

| 看到的现象 | 能说明什么 | 还缺什么 |
|---|---|---|
| 学右格后，旧左／前更多执行右格 | 条件行为退化，存在错目标分量 | 未定位损伤位置 |
| 对语言位置的注意力减少 | 某种统计变化 | 注意力大小不等于信息作用，不能据此定因果 |
| 探针能读出“左／前” | 相应信息可被额外读出器利用 | 可能只读到了词名，未证明接地或策略实际利用 |
| 换回旧输出差分可以救援 | 旧条件响应可提供补偿 | 尚未定位内部读取接口 |
| 恢复局部旧读取能救援，反向注入新读取复现同类错误 | 局部读取变化参与损伤的证据增强 | 仍需指令特异性、其他模块和独立复验 |
| 上述证据成立，针对性保护又改善新旧任务折中 | 解释对象具有可操作价值 | 仍不能说唯一成因或普适解决 |

[Encoded but Not in Control](https://arxiv.org/html/2610.06235v1) 区分了表示中可读的信息与实际控制动作的信息。我们可以参考其诊断思路，但当前冻结主干下“还能读出目标词”本身并不新颖，也不够证明读取出了问题。

## 4. 一次完整的机制验证怎么做

### 第一步：准备健康参照和受损模型

记正式合格的旧模型为 R0，学习右格后出现损伤的模型为 Rbad。开发期可以先用历史模型调接口，但表格须标注其资格限制。

先确认：R0 原来确实会按左／前选择；Rbad 的新右格有真实学习增益；旧能力损伤中有明确错目标，而非只有抓空、滑落或先成功后破坏。正式统计使用同一批物理初态前后配对，既报全部有效条件，也单列 R0 实际成功的条件。

### 第二步：用共同状态缩小行为阶段

先尝试构造合法的“书已抓稳、尚未进入任何格子”状态，验证 R0 从这里按左／前都能完成。

- 若 Rbad 从这里能正确放置，而完整任务总抓空，优先研究早期执行。
- 若从这里仍稳定选错格子，继续研究目标选择及读取。

中间状态只是诊断工具。最终还要从正常任务起点完成任务，不能用后半段成功代替完整技能恢复。状态不可合法构造时，报告无法开展，不硬造共同支持。

### 第三步：固定所有非语言输入，并审计上游材料

在同一次查询中，新旧分支共用当前画面、机器人状态、动作生成草稿 X_tau、生成进度 tau、mask、归一化和随机条件。左／前两条指令也共用同一 X_tau。

先检查图像／语言／状态前缀子块的实际差异，再做一个粗定位：让新旧动作专家读取同一份前缀，比较指令区分能力。这里 F 表示完整前缀，E 表示动作专家及其后端：

| 组合 | 用途 |
|---|---|
| F0＋E0 | 健康模型自重构基准 |
| F1＋E1 | 受损模型自重构基准 |
| F0＋E1 | 固定旧前缀后，新后端是否仍然受损？ |
| F1＋E0 | 新前缀交给旧后端，原能力是否还能工作？ |

其中“后端”包含较大一组计算。即使 F0＋E1 失败，也不能直接说是语言读取坏了；即使 F0＋E1 救回，也可能是状态前缀修复。若两检查点的图文子块已验证相同，仅交换这些相同子块不应产生实质收益，出现收益应先查实现。

这一步用于决定继续查上游材料、状态投影还是后端，不用于直接命名病灶。跨检查点混搭还可能存在接口不兼容。

### 第四步：只替换一个候选接口的读取分配或内容

不要一开始换整层。先在代码实际存在的少量候选接口做局部测试。当前模型交错使用自注意力和跨注意力；只查一组跨注意力失败，不能排除其他位置的读入变化。

在一个真实读取位置，简化写成：

    P = softmax(Q K^T / sqrt(d) + mask)
    读取结果 = P C

P 是“把多少读取权重分给哪些位置”；C 是投影后的 value 内容。P 和 C 都是矩阵，P 不是最终动作概率，C 也不保证是纯语言信息。代码对应注意力分配 probs 与 expert value 内容。

在 Rbad 运行背景下，固定当前输出投影、残差、MLP 和其余网络，只比较：

| 局部组合 | 通俗解释 |
|---|---|
| P新 C新 | 原始受损读取 |
| P旧 C新 | 用原来的读取分配读取现在的内容 |
| P新 C旧 | 用现在的读取分配读取原来的内容 |
| P旧 C旧 | 在该位置同时恢复分配和内容 |

最后一项仍不等于完整旧层，更不等于完整旧策略。旧 P/C 必须由旧模型在当前实时输入上计算，而不是拿初始画面的缓存用到结束。

若 P旧 C新 有效，只能先说“恢复旧读取分配对修复有功能贡献”。P旧 本身依赖旧 Q/K、旧隐藏状态及前缀，尚未证明错误由该层 Q/K 参数改变造成。若只有 C旧 有效，则应优先查内容变换，不能继续宣称“注意力分配就是病灶”。

### 第五步：证明这个接口真的在传递指令相关信息

同一模型、同一画面和状态，只改变两条已掌握的旧指令：左格与前格。取得候选接口在两条指令下的消息。

当前请求左格时，分别注入左格来源和前格来源的局部消息，观察：正确来源是否更能恢复左格；错误来源是否使行为有规律地偏向前格。两条指令反向也检查。我们需要“效果随来源目标改变”，而不只是“注入后模型有反应”。

首版可先比较该接口的指令依赖部分和共同部分：

    共同消息 = (消息左 + 消息前) / 2
    左区别   = (消息左 - 消息前) / 2
    前区别   = -左区别

此处消息可以选定为某个读取接口的输出；与最终动作输出差分是不同分析层级，不能混为同一证据。若在 softmax 后的 P 上交换差分，组合可能产生负数或破坏行和，不能默认它仍是合法注意力分配；应先在预定的消息输出位置做对照，或另行审计 logits 干预及归一化规则。

首版不必强行只换语言位置的注意力列。图文已融合、状态也可携带指令信息；局部列交换还会改变 softmax 总质量，必须与同列数、同质量的非目标位置干预比较。否则只能说某些 token 位置有效，不能说隔离了纯语言通路。

### 第六步：在健康背景下反向复现同类错误

只会救援不够：旧消息可能是在补偿其他地方的损伤。

再让 R0 作为接收模型，在同一预锁选择阶段换入 Rbad 的候选读取分配或消息。阶段外使用 R0；正向救援阶段外使用 Rbad。记录背景，不能把相同局部混合公式换个名字当成第二个独立发现。

理想结果是：旧读取帮助 Rbad 重新完成请求目标；新读取使 R0 出现相近的“旧左／前→新右格”错误。只让 R0 抓空、震荡或无法执行，不算复现目标替代。

正反向一致支持该功能变化参与损伤，不证明唯一成因。旧信息可能由参照模型重新注入，因此也不能据此宣称 Rbad 内部仍完整保留全部旧知识。反向失败也可能来自协同或混搭不兼容，不能直接证明该接口无关。

### 第七步：若要定位具体参数，再补更窄的参数验证

在开发证据支持的候选位置，分别测试小范围旧参数恢复、健康模型中的反向新参数移植，并与其他位置、相近参数规模的对照比较。仍需报告新右格表现。

激活替换定位的是某次计算的作用；参数替换检查某组权重的作用。两者不同。只微调一个位置能修好，也可能是该位置学会了补偿，不能倒推自然损伤一定发生在那里。

若只有后端整组恢复有效，就把结论停在后端兼容性／控制功能损伤；不能为得到“语言通路”结论不断扩大替换范围。

## 5. 实现与评价中不能省略的检查

1. **自替换恒等。** 同模型同输入重构 P/C 或消息，应复现原响应与配对执行；先排除 hook 和缓存污染。
2. **输入真的对应。** head、query/token 位置、padding、mask、RoPE、归一化、精度及动作时域须核对。不要按“第几个 token”盲目对应不同长度的句子。
3. **共同生成草稿。** 左／前不能各用自己的真实动作构造不同 X_tau，再把输出差归给语言；目标可能已通过动作草稿泄漏。优先使用实际采样过程中的共同噪声与当前草稿；训练锚点若使用统一参考动作，也要说明其来源，并跨生成进度检查是否出现语言信号被动作草稿掩盖的情况。
4. **实时而非陈旧信息。** 每次重规划读取当前观测；各干预轨迹之后自然分叉。不能假装它们全程看见同一串画面。
5. **窗口提前锁定。** 使用开发集确定且各指令仍可完成的阶段，不按测试中何时出错、哪次救回最好临时挑窗口。窗口外策略和实际覆盖量写进日志。
6. **假干预对照。** 正确／错误指令来源、共同消息恢复、等幅随机修正、非候选位置，以及状态投影和动作读出对照按证据逐步加入，不一开始铺全因子。
7. **两条旧指令都报告。** 当前首选旧条件是左／前；R0 未掌握的右／后不能当旧教师正确分支。不能只展示最容易救的指令或失败视频。
8. **完整执行是终点。** 报正确目标、各错目标、未完成、抓取／释放与成功后失效；响应距离和注意力图只辅助解释。正常起点与人工交接状态分表。
9. **独立复验。** 开发状态用于选位置，封存状态只按锁定规则执行。推理 seed 不等于训练 seed；正式关键结论至少三个独立训练起点／过程，并扩另一任务流。

当前接口的 K/V cache 在部分计算中会被追加或裁剪；实现多来源分支时要审计 cache 所有权与复用，不能让旧分支改写新分支缓存。单卡顺序推理或双卡各放一份模型只是工程选择，额外前向、传输、延迟和显存全部记录。

激活替换的指标、扰动与窗口选择本身会影响解释结果，已有系统研究对此给出直接警示。因此，预先锁定规则及报告负结果是方法有效性的一部分。[Activation Patching 最佳实践](https://arxiv.org/html/2309.16042v1)

## 6. 什么结果允许写什么结论

| 实际证据组合 | 可以写的结论 | 不应写的结论 |
|---|---|---|
| 只有注意力或探针变化 | 发现相关线索 | 已定位语言读取损伤 |
| 旧输出差分救回 | 条件响应可补偿行为损伤 | 找到了内部语言模块 |
| 局部旧读取救回，反向无特异复现 | 该接口可提供补偿 | 自然损伤唯一来自该接口 |
| 旧读取特异救回、新读取复现同类错误，指令来源改变对应目标，超过控制并独立复验 | 提供指令依赖读取变化参与所测退化的特异功能因果证据 | 纯语言通路是所有遗忘的唯一病灶 |
| 主要是状态前缀恢复有效 | 状态输入及其交互值得优先研究 | 语言语义丢失已被证明 |
| 内容或动作读出恢复更有效 | 内容传递／后续动作计算更值得研究 | 注意力读取分配必然是主因 |
| 所有部分替换都失效 | 当前分解或干预不足，也可能存在不兼容 | 所有语言读取假设被彻底否定 |

即使最强一行成立，也只证明当前具体指令条件的因果控制变化。两个目标词和固定布局仍可能形成任务键索引；开放语言理解、组合接地和跨布局泛化需要额外独立实验。

## 7. “恢复”要分成三种任务

| 类型 | 从哪里开始 | 做什么 | 能回答什么 |
|---|---|---|---|
| 事后救援诊断 | 已坏的 Rbad | 推理时借旧响应或局部旧参数 | 哪种干预可以恢复行为？ |
| 损伤后修复 | 已坏的 Rbad | 用允许的数据重新训练 | 旧能力能否找回，并保住新右格？ |
| 损伤前预防 | 合格 R0 | 重新学习右格，同时施加保护 | 继续学习时能否减少损伤？ |

三类结果分表。从 R0 重训得到好结果，叫预防，不能说修好了 Rbad；把整个模型退回 R0 虽然可能恢复旧能力，却可能直接失去新右格，也不算同时解决。

## 8. 可尝试的恢复与预防方法

### 8.1 普通有限 ER：必须先有的参照

**通俗解释：** 学新题时复习少量真实旧题。

预防沿用 10/24 计划：从封存双目标父模型分支，比较 FT4 与 4新＋1旧左＋1旧前的随机 ER。两分支均固定 12000 步，FT4 与 ER 的新损失每条都按 1/6 加权。先看普通复习能解决多少，不预设它失败。

若做损伤后修复，则所有修复方法从同一 Rbad 出发，用同一有限旧记忆和同一新右格数据继续训练。它检验重新学习是否已经足够，不能与前一种起点混排。

**局限：** 可能重复复习相似状态、漏掉关键选择阶段；也可能保旧但妨碍新学。具体原因要实测，不用“回放不够高级”代替解释。

### 8.2 局部旧参数恢复：先做低成本诊断

**通俗解释：** 只把怀疑损坏的小零件换回旧版本，检查能否恢复。

在已支持的候选接口恢复小范围旧权重，再测旧左／前和新右格。如果旧能力恢复而右格崩溃，说明存在功能冲突，尚未得到可用方案。按开发规则测试少量插值也可以，但插值权重必须预锁、给对照相同调参预算，不能逐测试回合挑最好值。

**身份：** 它主要是诊断与工程参照。跨检查点参数坐标或配合关系可能改变；未恢复不等于该部件无关。恢复成功也不自动证明语言特异性。

### 8.3 原条件区别蒸馏：保护换指令带来的动作变化

**通俗解释：** 允许模型为了新任务改变动作，但要求同状态下“左和前应有何不同”不要被学乱。

当前只有两个已掌握旧条件，记同一生成输入下的流场响应为 v左、v前：

    mu = (v左 + v前) / 2
    r左 = (v左 - v前) / 2
    r前 = -r左

学生匹配教师的 r，等价于保持左／前这一条跨指令响应差，只有一个独立差分。它不是找到了多个语言模块，也不是证明网络里分开存着 mu 与 r。

    总损失 = 新任务动作损失 + 旧事实动作回放 + lambda × 条件区别保持

从 Rbad 开始是修复候选；从 R0 学右格时加入是预防候选。无论哪种，都与相同状态、相同教师权限的完整动作输出蒸馏比较。

**何时可能有效：** 双向功能证据支持条件响应变化参与错目标。

**何时可能无效：** 所有指令共同偏向右格时，差分可以完全不变；最终动作读出或释放控制出问题时，保住差分也可能不能完成任务。该约束还可通过其他参数补偿，并不直接保护某条内部语言读取边。

保持输入变化引起的教师响应差已有方法基础，不能把此公式称作全新原理。[Cross-corruption distillation](https://onlinelibrary.wiley.com/doi/full/10.4218/etrij.2026-0159)；持续 VLA 的教师与结构保持也已有直接近邻。[Info-VLA](https://arxiv.org/html/2603.13335v1)

### 8.4 机制支持的局部消息保持：更直接保护读取接口

**通俗解释：** 若证据指向某个读取接口，就在旧状态上检查这段接口传递的指令相关消息，训练时少让它改变。

设 m 是预锁接口的消息输出，可先保持：

    d_m = m(z,左) - m(z,前)
    L_read = ||d_m学生 - d_m旧教师||²

也可研究注意力分配保持，但只有分配干预获得支持时才值得尝试；token 对齐、mask 和归一化必须一致。保整张分配矩阵可能过度约束本来有用的读取变化。

**候选优势：** 相比最终输出约束，它直接作用于经干预支持的中间功能。

**风险：** 内部坐标改变、内容变化、其他层绕过约束，都会使内部相似与行为保持脱节；消息不变也不保证后端正确利用。若选了冻结且不依赖可训练参数的张量，附加损失可能根本没有有效梯度，须实测它对许可参数的梯度，不能加一个无效正则当基线。

首版不同时堆消息保持、输出差分、参数惩罚三项。先单独比较保护对象；若功能差分证据强、内部定位弱，仍以原输出差分作最小候选，不硬加内部损失。

### 8.5 候选参数的小步保护或局部修复

**通俗解释：** 对已验证重要的小范围参数，学习新任务时少改一点；或者损伤后只在该范围做有限修复。

可比较：降低候选参数学习率、对其偏离旧值施加惩罚、只允许候选位置参与小预算修复。先不用“整组冻结”为主方法，因为这些读取计算也服务新任务。

**必须比较：** 相近参数规模的其他位置、相同更新权限下的普通修复，以及全许可动作侧参数更新。如果任意位置都能修好，不能说候选位置具有独特机制意义。若完全冻结后只保旧、右格学不会，就是限制可塑性，不是解决。

位置选择和参数正则都已有广泛基础。它们能否形成贡献，取决于该位置的特异证据及新旧折中，而非换一个方法名字。

### 8.6 有真实支持的多指令训练与互补选样

若旧状态有多条指令对应的合法、真实动作演示，可以比较配对训练；没有对应专家动作时，其他指令只能获得经验证教师的蒸馏目标，不能把左格真实动作改个标签当成前格演示。新增采集和环境访问须另列权限与成本。

互补选样则改变有限记忆保留哪些状态，让同样的蒸馏有机会检查不同损伤方向。它改变的是监督覆盖，不能修复所有机制，也不自动等于恢复了语言读取。

仍按四因素组验证：A随机ER、B随机状态＋原蒸馏、C互补选样ER、D互补选样＋原蒸馏。D 对 B 才检验选样对原蒸馏的额外价值；完整输出蒸馏也应允许使用同一选择器。没有机制和普通回放缺口前，不先投入大规模评分。

### 8.7 条件增强与通用稳定训练：相关对照，不是损伤确诊

若简单增强当前条件响应就有效，可能主要是强度或共同偏移问题，未必需要保持全部旧差分。CAG 用条件／无语言分支做推理引导，是相关参照；我们的多合法指令均值不是其无语言分支，不能把 mu＋alpha r 直接当作忠实 CAG 复现。[LIBERO-CF / CAG](https://arxiv.org/html/2602.17659v1)

SAM 也是相关训练对照，已有 VLA 工作将其用于缓解微调后的指令盲视。但在本实验有效仍需验证，额外梯度与卡时必须计入。[Flatness Preserves Instruction Following](https://arxiv.org/html/2606.23641v1)

## 9. 恢复方法应该怎样公平比较

### 9.1 两张表，分别回答修复和预防

| 修复实验：都从同一 Rbad 出发 | 核心作用 |
|---|---|
| 不再训练的 Rbad | 当前损伤基线 |
| 有限事实回放修复 | 重新学习是否已经足够 |
| 相同回放＋完整输出 KD | 普通教师保持参照 |
| 相同回放＋输出区别 KD | 检查选择保护对象是否有收益 |
| 一个机制支持的局部候选 | 检查局部消息／参数方案，首轮只选一个 |

| 预防实验：都从同一合格 R0 学右格 | 核心作用 |
|---|---|
| 常规 FT、匹配 FT4 | 新学习与曝光控制 |
| 有限 ER | 普通复习基准 |
| 相同 ER＋完整输出 KD | 完整保持参照 |
| 相同 ER＋一个机制支持候选 | 是否提前减少损伤并允许新学习 |

所有修复分支使用相同额外步数、新样本序列、旧记忆及损失口径；所有预防分支匹配相应任务曝光、初始化及优化器规则。损失系数同数值不等于梯度强度相同，小型权重搜索预算须相同。额外前向和教师查询不伪称等计算。

### 9.2 旧数据和教师权限要讲清楚

- 损伤后的修复也只能用当时实际保留的旧记忆；不能为新方法重新扫描完整旧视频或正式失败状态。
- 教师缓存基于保留输入；图像、噪声或生成进度改变时，相应目标也重算。不能缓存旧输入响应却对新输入直接使用。
- 旧 R0 checkpoint 若允许作训练教师，完整 KD 与候选均应有同样权限，并披露其保存与查询成本；不能只给新方法免费旧知识。
- 历史样本、教师缓存和索引合并核算。若沿用 64MiB，缓存就要占这份额度；无教师方法可在等字节表中多存真实样本。模型／辅助教师权重单列；若未来总记忆协议也计教师权重，必须统一修改口径。
- 机制诊断中的旧模型、模拟器交接与额外查询是分析资源，不自动转成在线持续学习方法的合法免费数据。

## 10. 怎样判定真的修复，而不是换了一个问题

至少同时报告：

1. 旧左／前正确目标的完整成功与终态保持，以及同初态双指令共同正确。
2. 旧指令→新右格、其他错目标、未完成的比例；以同一确认集的实际前成功条件计算保持和新发替代。
3. 新右格相对 R0 的学习增益，以及修复前后是否丢掉新技能。
4. 请求目标曾成功、最终正确、首次到达、最长连续成功及先成功后失效。
5. 缓存内与未缓存状态分别报告；关键结论不能只有训练记忆拟合改善。
6. 训练与教师计算量、记忆字节、推理延迟、峰值显存和实际额外评估回合。

“旧能力恢复更多、右格同样好”，或者“旧能力同样好、右格学得更多”，才支持更好的新旧折中。以不同权重得到的曲线比较，不给完整 KD 故意选一个过强系数再宣布胜出。

只从人工交接状态成功、只让动作方向偏转、只让注意力或损失恢复，都不等于完整技能修复。只对旧任务使用更短时限或成功即停止，也不能放入原协议主表。

## 11. 结合现状，建议按四个闸门推进

| 闸门 | 实际工作 | 何时继续 |
|---|---|---|
| G1：普通ER | 完成10/24计划2A的FT4／ER；再按2B补起点和独立确认 | 新任务有增益，且存在值得研究的残留损伤 |
| G2：局部因果诊断 | cache分块审计、共同状态、一个接口的救援／反向及特异控制 | 局部读取证据超过补偿和执行解释 |
| G3：小预算修复 | 从同Rbad比较事实回放、完整KD和一个候选 | 学生独立改善旧能力，新右格未被明显牺牲 |
| G4：预防与泛化 | 从合格R0重新学右格，独立种子和另一任务流复验；再考虑互补选样 | 同权限下优势可复验且成本合理 |

G2 的接口调试可先用 4 个开发共同状态×2 条旧指令×4 条核心条件＝32 次执行，核心条件为健康、受损、局部救援、反向注入。这只检查实现和大信号；它不是正式证据，实际未必有四个合格共同状态。错误来源、随机、共同消息、其他模块、新右格及完整起点评估均需另计。先实测接口有效性和延迟，再登记下一轮配额，不承诺一晚上跑完全部组合。

开发候选接口可先限定为少量预选层／头组和明确生成阶段，而非全层全头全时间扫描。只筛最显著位置会产生选择偏差，所以必须锁定后在封存组验证。两张3090可以各放一份参照／受损模型做诊断，也可以单卡顺序推理；它们不会自动合并显存，运行安排以实测为准。

若 ER 已在当前预算下保住旧目标且学好右格，先复验并收窄新方法动机；若主要剩执行或维持问题，先转向相应诊断。不要为保留“语言读取损伤”叙事而无限增加训练压力或改变任务。

## 12. 哪些相关研究必须参考，创新边界在哪里

| 工作 | 与本文相关的已有内容 | 我们不能重复声称什么 |
|---|---|---|
| [Encoded but Not in Control](https://arxiv.org/html/2610.06235v1) | 可读信息与动作控制之间的差距 | 探针能读出目标就证明已经接地或找到了读取病灶 |
| [When Instructions Retrieve Trajectories / ECT](https://arxiv.org/html/2609.39971v1) | 前缀K/V诊断和替换、任务方向操纵、训练支持问题 | 内部替换及指令键式行为是全新发现；其持续注入不等于完整技能恢复 |
| [Do VLA Models Understand Instructions?](https://arxiv.org/html/2610.10178v1) | 动作生成模块的激活／归因替换及指令扰动 | 首次对VLA语言影响做机制干预；离线动作变化直接等于正确闭环目标 |
| [Activation Patching 最佳实践](https://arxiv.org/html/2309.16042v1) | 指标与扰动方式影响因果定位 | 任意一个热图或单次救援就提供稳定定位 |
| [Goodfire：VLM—动作专家接口分析](https://docs.goodfire.com/assets/reports/vla-interface.html) | 接口替换、层消融及据此设计更高效架构；属于研究机构技术报告 | 首次发现动作专家可能依赖少数读取连接；其具体层号可直接搬到SmolVLA |
| [Info-VLA](https://arxiv.org/html/2603.13335v1) | 持续VLA中的教师、回放与跨模态结构保持 | “持续学习会破坏跨模态关系，教师可保持结构”本身无人研究 |
| [Cross-corruption distillation](https://onlinelibrary.wiley.com/doi/full/10.4218/etrij.2026-0159) | 对输入变化引起的教师响应差做蒸馏 | 条件响应差蒸馏是全新损失家族 |
| [LIBERO-CF / CAG](https://arxiv.org/html/2602.17659v1)、[Flatness Preserves Instruction Following](https://arxiv.org/html/2606.23641v1) | 条件推理引导、微调指令盲视及SAM缓解 | 只靠增强语言信号或换优化器就足以构成独立新原理 |

上述工作支持我们使用这些工具，也构成必须面对的重叠。本文真正可能争取的是：**在原已掌握的条件选择中，发现后续学习引起的可复验失效；建立某个指令依赖读取变化的特异因果证据；再由此获得超出强回放及完整保持的实际新旧折中。**

如果只得到“又一次看到语言被忽略＋某个蒸馏略有提高”，创新仍然偏弱。若只有输出功能证据，就如实写功能研究；若完整 KD 一样好，就不强调差分保护优势；若任意位置均能修复，就不强调内部通路定位。新名称和更复杂的控制表不替代新的可复验发现。

## 13. 可以对导师口述的一段话

> 我们已经在无回放的探索中看到：原来能按左、前指令分别完成的机器人，继续学右格后会把旧指令也做成右格。但现在还不知道是哪一段计算出了问题。下一步先检验普通有限回放能解决多少；有残留问题后，只替换一个候选读取接口，既检查能不能救回，也检查把新接口放进健康模型后会不会出现同类错误，并与状态和动作控制变化作对照。只有这些证据指向指令相关读取，我们才做局部修复或蒸馏保护；最后要求学生独立运行时，既恢复旧目标选择，也保住新右格。我们允许普通回放足够、损伤主要在控制端等结果推翻原假设，不提前把它包装成已经证明的语言模块遗忘。
