## 1. 登录并准备终端

在你自己电脑的终端执行：

```bash
ssh scutlab
cd ~/cl_binding
git pull --ff-only origin main
source .venv/bin/activate

set -o pipefail
export MUJOCO_GL=egl
export LIBERO_CONFIG_PATH="$PWD/.server/libero"
export TOKENIZERS_PARALLELISM=false
export OMP_NUM_THREADS=4
mkdir -p .server/smoke
nvidia-smi
```

后面的命令都在服务器的 `~/cl_binding` 中执行。不要切回系统 Python，也不要激活旧 Conda。`nvidia-smi` 应能看到两张 24GB RTX 3090；如果有其他人的训练占满显存，先不要启动模型步骤。

下面示例训练目录为 `outputs/smoke/train_001`，闭环输出为 `outputs/smoke/rollout_001`。脚本会拒绝覆盖已有输出；再次跑时把编号改成 `002`，并同步修改闭环命令中的 checkpoint 路径。不要为了重跑删除原始演示或预训练权重。

## 3. 检查原始演示

```bash
python -u scripts/stage1_smoke.py inspect \
  2>&1 | tee .server/smoke/01_raw_inspection.log
```

它打开四份 HDF5，检查首条演示的语言、相机、状态和动作。报告保存在 `.server/smoke/raw_inspection.json`。

通过标准：四个方向都能打印出报告，语言包含对应的方向，状态为 `T×8`，动作为 `T×7`，相机为 `T×128×128×3`；数值没有 NaN/Inf。`T` 是该条轨迹的帧数，不同任务可以不同。

这一步只核对输入格式和首条演示，不等于全部 50 条轨迹都已通过任务质量检查。

## 4. 转换很小的冒烟数据集

每个方向只取第一条完整演示；先把三个旧目标放一起，把后格 N1 单独存放：

```bash
python -u scripts/stage1_smoke.py convert \
  --goals front left right \
  --episodes-per-task 1 \
  --output datasets/stage1_smoke_old \
  2>&1 | tee .server/smoke/02_convert_old.log

python -u scripts/stage1_smoke.py convert \
  --goals back \
  --episodes-per-task 1 \
  --output datasets/stage1_smoke_n1 \
  2>&1 | tee .server/smoke/03_convert_n1.log
```

通过标准：两条命令分别打印 `CONVERSION PASS`。目录内应包含 LeRobot 元数据、Parquet、双相机 MP4 和 `smoke_conversion.json`。相同配置已转换完成时打印 `REUSE`，不会重复转换。不要提前手动创建这两个目标目录；转换中断后应检查原因并换新输出目录。

具体映射固定如下，训练与闭环推理使用相同约定：

| 原始数据 | 模型输入 / 处理 |
|---|---|
| `agentview_rgb` | `observation.images.image`，外部相机 |
| `eye_in_hand_rgb` | `observation.images.image2`，手腕相机 |
| 两个 RGB 图像 | 高、宽两轴均翻转，旋转 180°；与当前 LeRobot 的 LIBERO 图像约定一致 |
| `ee_states` 的 6 维 + `gripper_states` 的 2 维 | 8 维状态：末端位置、轴角姿态、双指位置 |
| 原始 `actions` | 保留 7 维相对 `OSC_POSE` 控制动作，不重新缩放、不改时间索引 |
| `problem_info.language_instruction` | 保留完整原始英文指令 |

视频按 20 FPS 编码为 H.264；本轮使用 PyAV 读取。首帧预览在 `.server/smoke/previews/`，可以用服务器文件面板或下载后查看，确认两个相机都能看清书、机器人和收纳盒。

**本轮训练只读取 `stage1_smoke_old`，归一化统计也只取三个旧目标。** `stage1_smoke_n1` 此时仅检验后格数据能否转换，不加入这 5 步训练。每目标一条轨迹只用于冒烟，不能拿来建立正式 R0 或报告成功率。

## 5. 严格加载主基座

```bash
CUDA_VISIBLE_DEVICES=0 python -u scripts/stage1_smoke.py load \
  2>&1 | tee .server/smoke/04_model_load.log
```

通过标准：最后的 JSON 有 `"status": "pass"`、`"strict_loading": true`，报告保存在 `.server/smoke/model_load.json`。如果报权重缺失、键不匹配或形状不匹配，停在这里，不要改成 `strict=False` 跳过。

脚本会把默认输入适配成双相机、8 维状态和 7 维动作。内部状态/动作投影仍为原来的 32 维上限，保持 checkpoint 参数形状；数据按旧任务统计重新归一化，不复用基座默认的 6 维统计。

这里的 `load_vlm_weights=False` 表示构造阶段只读本地 VLM 配置，随后**严格加载完整 SmolVLA 策略权重**。它用于避免再次下载独立 VLM 权重，不是用随机 VLM 开始训练。

## 6. 真正做 5 步更新，并检查保存重载

```bash
CUDA_VISIBLE_DEVICES=0 python -u scripts/stage1_smoke.py train \
  --dataset datasets/stage1_smoke_old \
  --run-dir outputs/smoke/train_001 \
  --steps 5 \
  2>&1 | tee .server/smoke/05_train.log
```

本轮固定 batch size 为 1、BF16 autocast、`num_workers=0`，冻结 VLM，仅更新当前 SmolVLA 配置中的动作专家和相关投影。学习率为 `1e-5`，不接入回放、蒸馏、LoRA 或实验跟踪服务。

脚本按顺序完成：

1. 从本地 LeRobot 数据集解码真实双相机视频，读取 50 步动作窗口和语言。
2. 做前向、反向、有限梯度检查及优化器更新，累计 5 步。
3. 检查动作输出投影的参数确实发生变化。
4. 保存模型和前后处理器到 `outputs/smoke/train_001/checkpoint/`。
5. 重新构造模型并严格加载这个 checkpoint，用同一个输入、同一份采样噪声比较保存前后的动作预测。

通过标准：

- 打印 5 条 step 记录，loss 和梯度范数均有限，梯度范数大于 0。
- 最终 `outputs/smoke/train_001/train_smoke.json` 的 `status` 为 `pass`。
- `updated_projection_max_delta > 0`。
- `save_reload_max_difference` 满足脚本的 `atol=rtol=1e-3` 比较。
- `action_shape` 为 `[1, 50, 7]`，动作没有 NaN/Inf。
- 报告中包含双相机解码结果和 `peak_training_allocated_mib`。

**不要求这 5 个 loss 连续下降。** Flow matching 每次会采样噪声和时间，批次也不同；短程冒烟看的是数值、梯度、参数更新和重载一致性。

此处重载的是模型与处理器；尚未验证优化器、调度器和随机数状态的完整断点续训。这个 checkpoint 也不是合格 R0。

## 7. 用第二张卡做短程闭环

先等第 6 步结束，再执行：

```bash
CUDA_VISIBLE_DEVICES=1 python -u scripts/stage1_smoke.py rollout \
  --checkpoint outputs/smoke/train_001/checkpoint \
  --output outputs/smoke/rollout_001 \
  --steps 8 \
  2>&1 | tee .server/smoke/06_rollout.log
```

`CUDA_VISIBLE_DEVICES=1` 让模型在物理第 1 张卡上运行，进程内部仍把它叫作 `cuda:0`，这是正常的。

脚本依次打开前、左、右、后四个任务，使用各任务第 0 个初态，先做 10 步空动作让物体稳定，再输入对应语言和双相机观察。之后让模型输出 7 维动作，经反归一化并裁剪到控制器的 `[-1, 1]` 范围后执行，最多 8 步。两相机的首尾预览、原始/实际执行动作和报告都在输出目录。

通过标准：`outputs/smoke/rollout_001/rollout_smoke.json` 顶层 `status` 为 `pass`，四个任务都完成短程执行，无维度错误、NaN、渲染崩溃或断开的模型调用。

**`task_success: false` 在这里完全可能出现，不算冒烟失败。** 几步更新和 8 步闭环都不足以证明任务能力；这里检查的是“观察 → 语言处理 → 模型 → 动作 → 仿真”的连接。不同任务用各自的初态，本步骤也不是共用初态的成对因果诊断。

## 8. 常见失败怎么处理

| 现象 | 应对 |
|---|---|
| `Missing raw demonstrations` | 回到第 2 步，完成四份演示下载后重跑清单 |
| 找不到 VLM metadata / 离线缓存缺文件 | 检查 `.server/resources.json` 的 `metadata_path`，用下载脚本补齐小文件，不另下一份完整 VLM |
| `Refusing to overwrite` / `Choose a new --run-dir` | 换新输出编号；不要删除原始数据或主基座 |
| CUDA OOM | 用 `nvidia-smi` 核对其他进程和所选卡；当前已是 batch=1，不要同时开多份模型；先保留错误日志 |
| 视频或元数据读取失败 | 检查转换是否出现 `CONVERSION PASS`、是否有 `smoke_conversion.json`；不要把未 finalize 的目录当成完成数据集 |
| 下载日志长时间只有 `Fetching 4 files: 0/4` | 单个文件约 0.61–0.75GB，完成一份才推进计数；用 `du -sh datasets/raw` 观察磁盘上的增长，不要同时启动另一份下载 |
| 严格加载失败 | 保留完整报错；核对固定代码和权重版本，不忽略 missing/unexpected keys |
| EGL / 初态路径失败 | 执行 `python scripts/verify_scutlab.py --render-smoke`，检查 `.server/libero/config.yaml` 与素材缓存 |
| 看到 “Downloading from HuggingFace Hub” 随后紧接 “Assets already downloaded” | 这是上游素材定位提示；若后者指向已有缓存，不表示重新下载了素材 |
